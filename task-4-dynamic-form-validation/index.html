About This Project

Task 4 – Complex Form Validation and Dynamic DOM Manipulation

This project builds on Tasks 1 to 3 of the Full Stack Development Internship. It focuses on three things: checking form input thoroughly as the user types, updating the page dynamically without a reload, and moving between views with client-side routing instead of separate HTML files.

Complex Form Validation

The registration form checks each field as the user types, not only on submit. The password field has five separate rules (length, uppercase, lowercase, number, special character) and a four-segment strength meter that reacts to how many rules currently pass. The username field is checked against the users already saved in this browser, so a duplicate name is caught before submitting.

Dynamic DOM Manipulation

The Users dashboard keeps its data in a plain JavaScript array and re-renders only the rows that changed. Typing in the search box, changing the sort order, editing a bio, or deleting a user all update the page instantly through createElement, textContent and class changes — there is no server involved.

Client-Side Routing

Home, Register, Users and About are four sections in one index.html. A small router in js/router.js reads location.hash, shows the matching section, hides the rest, and updates the active link in the navbar. The browser's Back and Forward buttons, and reloading the page on any route, all work correctly because the route lives in the URL.

Storage Note

This task has no backend, so registered users are kept in this browser's localStorage only. They are not sent anywhere, and clearing your browser data or using a different browser or device will not show the same list.
